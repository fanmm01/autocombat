# 自走棋「半变身模式 + 单卡星级微调」详细实施规格书

> 文档用途：供后续执行者直接按规格编码、联调与回归验收。
> 前置状态：仓库当前已包含 `Y19 木落-焚秋`（`hp_ratio <= 0.35` 才放四技能夕阳）与 `Y8 比哈米`（`BIHAMI_CAKE_SCALING` 星级蛋糕、款待解锁与队友自动吃蛋糕）的改动，本规格书在此基础上叠加实施。

## 1. 实施范围与硬性边界

### 1.1 两大交付模块

1. **模块 A（双模式共享生效）：`Y17`、`Y11`、`Y6`、`Y12`、`Y1` 的星级调整**
   - **`Y17 夜诏明`（已实施）**：两模式使用 `SHARED_STAR_OVERRIDES['Y17']`。2★ 补强体力、伤害与吸血，3★ 补强体力与伤害。半变身 2★、3★ 目标分别为 `~35`、`~63`。两模式模拟复测见第 4 节。
   - **`Y11 蓝`（已实施）**：两模式使用 `SHARED_STAR_OVERRIDES['Y11']`，并移除 `UNIT_CATALOG['Y11']` 的 `flat_dmg_offset: 1`：
     - **1★**：总 `flat_dmg` 由 `+1` 降至 `0`，强度由 `39.3` 略降至 **`~37`**；
     - **2★**：沿用方案 2 的成长倍率（`hp_mult 1.45×`、`skill_bonus +6`、总 `flat_dmg +1`）；
     - **3★**：采用双模式共享的 `extra_dmg_pct +12%`、`extra_flat_dmg +1`（总 `flat_dmg +4`）、额外吸血 `+8%`，半变身强度目标为 `~62`。
   - **`Y6 雪人`（已实施）**：双模式共用第 2.2 节的 3★ 覆写。半变身 3★ 目标 `~68`，旧报告为 `68.1`，四组全棋池均值为 `60.3`。
   - **`Y12 斯瑞提卡`（已实施）**：双模式共用 3★ 的 `summon_hp_mult = 2.65`、`summon_skill_bonus = 22` 与 `flat_dr = 2`。标准模式保留召唤物 `0.55` 补正，半变身沿用第 2.4 节的召唤规则。
   - **`Y1 炎焱`（已实施）**：双模式仅将 3★ 体力倍率从 `2.60` 提到 `2.75`，小幅提升生存能力。

2. **模块 B（已实施）：半变身新模式（4 人局 + 8 人排位）**
   - **战斗机制**：全棋子开局应用 **1/2 经典 `.hs` 变身** + 全召唤物采用 **1/2 经典设定**（取消 `Y12` 的 `0.55` 偏移）。
   - **唯一模式专属星级覆写**：`Y16 罗杰`仅在半变身 1★ 使用 `hp_mult = 0.80`，无羁绊、无强化符文时体力从 `62` 降到 `50`。强度目标为同池其他 1★ 的最高分附近，四组均值离首位约 `4.1` 分，见第 4.4 节。
   - **专属经济系统**：已确认采用 **四级制花费分档（1G–4G，取消 5G/6G 档）** 与配套商店概率表 `LEVEL_TABLE_HALF_HS`。
   - **玩法入口**：
     - 4 人标准局：`mode = 'lobby4', ruleset = 'half_hs'`；
     - 8 人排位赛：`mode = 'ranked', ruleset = 'half_hs'`（独立段位、积分、保段卡与排行榜 `ranked_half_hs`，局外金币 `coins` 与标准排位共用）。

### 1.2 硬性红线（执行者必须遵守）

1. **严禁污染全局模板**：不得原地修改 `characters_data.ALL_CHARACTERS`、`characters_data.SUMMON_TEMPLATES`、`autochess_catalog.UNIT_CATALOG`、`autochess_catalog.STAR_SCALING`。
2. **星级共享与模式隔离**：`standard` 与 `half_hs` 均使用第 2.2 节的 `SHARED_STAR_OVERRIDES`。`standard` 继续使用原有英雄模板、召唤模板、`Y12` 的 `0.55` 补正、`Y16` 的 1★ 全局倍率，以及原有费用与商店概率。
3. **严格星级单调性**：每名棋子的每项生效数值必须满足 `1★ <= 2★ <= 3★`（核心成长项 `1★ < 2★ < 3★`），严禁出现“2★ 多一个能力或数值更高、3★ 反而降回去或消失”。
4. **完全向后兼容**：所有既有函数/接口/历史存档缺省 `ruleset` 时一律默认为 `'standard'`。

#### 字段语义与合并规则
定义辅助函数 `_effective_star_override(serial, star, ruleset)`:
- 先取 `SHARED_STAR_OVERRIDES.get(serial, {}).get(star, {})`；
- 若 `normalize_ruleset(ruleset) == 'half_hs'`，再用 `HALF_HS_STAR_OVERRIDES.get(serial, {}).get(star, {})` 覆盖/合并；
- **覆写型字段**（替代 `STAR_SCALING[star]` 的对应项）：`hp_mult`、`mp_mult`、`skill_bonus`、`flat_dmg`、`flat_dr`、`summon_hp_mult`、`summon_skill_bonus`；
- **追加型字段**（在原计算结果上累加）：`extra_dmg_pct`、`extra_flat_dmg`、`extra_flat_dr`、`extra_bloodmoon_leech_pct`；
- **技能改写字段**：`guard_dr`（仅作用于 `cdata = copy.deepcopy(raw)` 副本内 `skill_id == 'Y17-S003'` 且 `eff.get('辅助效果') == '受到伤害加值'` 的 `eff['辅助效果值'] = str(guard_dr)`，**必须在 `load_character_to_engine(engine, cdata, uid)` 之前执行**）。

### 2.3 半变身英雄变身公式（1/2 经典 `.hs`）

严格对照 `backend/battle_engine.py:5218-5252` 的经典 `.hs` 逻辑，在 `apply_autochess_modifiers` 中、**紧接 `load_character_to_engine(engine, cdata, uid)` 之后、计算 `STAR_SCALING` / `hp_offset` / 羁绊之前**执行（仅当 `ruleset == 'half_hs'`）：

```python
def apply_half_hs_transform(engine, uid, serial):
    from battle_engine import ALL_COMBAT_SKILLS, _DB_TABLE

    char = engine.get_char(uid)
    combat_skills = list(ALL_COMBAT_SKILLS) + (['弓术'] if serial == 'Y17' else [])
    char.hs_orig = {
        '体力上限': char.get_attr('体力上限', 10),
        '体力': char.get_attr('体力', 10),
        '魔力上限': char.get_attr('魔力上限', 10),
        '魔力': char.get_attr('魔力', 10),
        '闪避': char.get_attr('闪避', 25),
        '体格': char.get_attr('体格', 0),
        '行动力': char.get_attr('行动力', 8),
        'skills': {sk: char.get_attr(sk) for sk in combat_skills if char.get_attr(sk) > 0},
    }
    char.hs_transformed = True
    level = char.get_attr('等级', 1) or 1
    ohp = char.get_attr('体力上限', char.get_attr('体力', 10))
    omp = char.get_attr('魔力上限', char.get_attr('魔力', 10))
    nhp = max(1, int(ohp * (5 + level) / 2.0))
    nmp = max(0, int(omp * (2 + 0.5 * level) / 2.0))
    char.set_attr('体力上限', nhp)
    char.set_attr('体力', nhp)
    char.set_attr('魔力上限', nmp)
    char.set_attr('魔力', nmp)
    dodge = char.get_attr('闪避', 25)
    char.set_attr('闪避', max(dodge, min(dodge + 20, 80)))
    char.set_attr('体格', char.get_attr('体格', 0) + 1)
    char.set_attr('行动力', char.get_attr('行动力', 8) + 3)
    for sk in combat_skills:
        v = char.get_attr(sk)
        if v > 0:
            char.set_attr(sk, max(v, min(v + 20, 80)))
    new_build = char.get_attr('体格', 0)
    char.set_str('db', _DB_TABLE.get(int(new_build), '0'))
```

> 关键点：
> - `char.hs_transformed = True` 会自动激活 `Y5`/`Y13` 的飞行判定（`battle_engine.py:10928,11351`），并将 `Y16` 召唤「虚假之月」的施法耗蓝切换为 `2d3`。
> - `Y19` 变身后 `剑` 技能在 `ALL_COMBAT_SKILLS` 之外（`Y19` 技能键名为 `'剑'`），请核对 `ALL_COMBAT_SKILLS` 是否包含 `'剑'`；若不包含，需确认是否沿用经典 `.hs` 行为（实测基准脚本中未额外加入 `'剑'`，保持与经典 `.hs` 一致即可）。

### 2.4 半变身召唤物快照（1/2 经典设定）

在 `backend/autochess_catalog.py` 中新增：

```python
def build_half_hs_summon_templates():
    from characters_data import SUMMON_TEMPLATES
    snap = copy.deepcopy(SUMMON_TEMPLATES)
    for name, tmpl in snap.items():
        if not isinstance(tmpl, dict) or tmpl.get('_meta') or name == '虚假之月':
            continue
        for field in ('HP', 'MP', 'shield_block'):
            val = tmpl.get(field)
            if isinstance(val, (int, float)) and val > 0:
                tmpl[field] = max(1, int(round(val * 0.5)))
    return snap
```

生效方式：
1. 在 `apply_autochess_modifiers(..., ruleset='standard')` 中：
   - 当 `ruleset == 'half_hs'` 且 `getattr(engine, '_summon_templates_snapshot', None) is None` 时，设置 `engine._summon_templates_snapshot = build_half_hs_summon_templates()`；
   - 当 `ruleset == 'half_hs'` 时，忽略 `UNIT_CATALOG['Y12']['summon_hp_mult_offset']`（即 `sum_offset = 1.0 if ruleset == 'half_hs' else float(meta.get('summon_hp_mult_offset', 1.0) or 1.0)`）。
2. 因为 `battle_engine.py` 的 `_create_summon`、`_check_trinity_merge`、`_get_summon_template` 均优先读取 `self._summon_templates_snapshot`，该方案天然实现 **引擎实例级隔离**，绝不影响经典模式或标准自走棋模式。

### 4.4 `Y16 罗杰` 1★ 与标准模式兼容性

此前定向测试中，`hp_mult = 0.80` 时 `Y16` 1★ 从 `52.3` 到 `52.1`，同批 `Y12` 参照为 `53.1`。四组全棋池在合并调参后，`Y16` 半变身 1★ 平均为 `45.2 → 43.7`，排名第 4 → 第 5，离调整后最高的 `Y6`（`47.8`）约 `4.1` 分。均强为 `55.4 → 54.8`，排名第 3 → 第 5。1★ 的逐组分差为 `−8.3 / −2.3 / +3.0 / +1.6`。

若只把同一 `0.80` 倍率同步到标准模式，1★ 体力会从 `14` 降到 `11`，四组 1★ 均下降，平均 `40.8 → 37.4`（`−3.4`，第 11 → 第 13），均强 `48.0 → 46.9`。规格将覆写限定在 `half_hs` 1★，两模式的 2★、3★ 继续采用全局倍率。
