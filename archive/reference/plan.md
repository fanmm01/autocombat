## Plan: 新状态效果与单槽多主动作

在统一状态查询层上实现“沉默、缴械、击晕、禁锢、隔离、减速、飞行”，让 Python 交互后端、完整/快速战斗、AI 训练模拟和 SealDice 本地模式共享相同限制；同时删除按 MOV 复制先攻条目的机制，改为每实体仅一个先攻条目，并在该回合内按有效 MOV 计算主动作数。状态效果使用辅助效果类型表达，辅助效果值即持续回合数；同类状态重复施加时取当前与新持续时间的较大值。

**Steps**

### 阶段一：统一状态模型与数据契约
1. 在 `autocombat/battle_engine.py` 增加标准状态常量和查询辅助方法，例如 `CONTROL_STATUS_TYPES`、`_get_active_statuses()`、`_has_status()`、`_can_move()`、`_can_basic_attack()`、`_can_cast_active_skill()`、`_can_take_active_action()`；状态 UID 必须经过 `_resolve_uid()`，召唤物与普通角色统一处理。把 `沉默/缴械/击晕/禁锢/隔离/减速/飞行` 作为 type=4 辅助效果的 `auxType`，将 `auxVal` 解析为持续回合数并写入 `remainingRounds`，而不是把数值当作强度。
2. 修改 `_execute_spell()` 的 type=4 分支：对控制状态采用“同状态+同目标”去重，持续时间刷新为 `max(当前剩余, 新效果值)`；保留来源技能名称用于显示。普通 AUX 继续沿用 `持续回合`。在 `characters_data.py` 与 `characters_data_pvp.py` 的 chData 字段说明中补充七种状态的写法、语义、重复施加规则和示例，避免角色数据作者误用。
3. 隔离采用“暂停后恢复”：状态查询时，目标处于隔离则忽略其来源为被动技能的 buff/护盾/领域等效果；被动效果本体不倒计时、不删除。为被动自动施放产生的效果记录 `sourcePassive=True`，并在 `_tick_down()` 中跳过这些效果的倒计时；隔离结束后原剩余时长和效果恢复。战斗开始、阶段切换、动态加入角色等自动被动入口在执行前检查隔离，避免隔离中的角色重新创建被动效果。

### 阶段二：落实每种状态的规则
4. 在所有执行入口集中执行限制，并让低层引擎作为最终防线：
   - 沉默：禁止 `.s1+` 及 `.a sN` 等非被动技能；`.s0` 可用，被动仍生效。
   - 缴械：禁止 `.s0`/自定义普通攻击；其他技能和移动可用。
   - 击晕：禁止移动、普通攻击、主动/附加技能及所有反应（闪避、反击、格挡），但允许 `.a eat`/`.a give` 和 `.i end`，被动继续生效。击晕的 `辅助效果值` 改为 `0/1`：`1` 表示击晕期间仍可成为普通攻击或含伤害效果技能的目标，`0` 表示不能成为攻击类行为的目标；非伤害控制/辅助类敌方效果仍可选中。持续时间读取标准 `持续回合` 字段。
   - 禁锢：仅禁止显式移动和攻击前自动接近；已在射程内的攻击/技能可正常执行。
   - 隔离：暂停该角色全部被动技能及其既有被动产物，主动行为不受限。
   - 减速：`辅助效果值` 是小数倍率（如 `0.5` 表示 MOV 变为 50%，`0.7` 表示变为 70%），持续时间改由标准 `持续回合` 字段提供；有效移动力在其他加减值结算后乘以所有减速倍率并向下取整、不低于 0。同名减速刷新持续时间取较大值，不重复叠加；不同来源的减速是否相乘沿用普通可叠加规则。
   - 飞行：所有来源（角色固有 `飞行`、buff `auxType=飞行`、召唤物 `flying`）统一令有效移动力 +8，不再直接给予攻击奖励骰；保留非飞行单位不能近战飞行目标的现有规则。
5. 修改 `_get_move_power()`、`_move_to_attack_range()`、显式移动处理和 `_coc7_attack()`/法术成功率检定：减速倍率和飞行只在统一有效 MOV 计算中应用一次；禁锢/击晕令移动预算为 0。将现有行动力奖惩规则改为基于双方有效 MOV：差值达到 5 时沿用既有高 MOV 方优势处理及 `_calc_net_bp()` 的合并/抵消路径；不再设置飞行专属奖励骰。普通攻击、法术攻击和召唤物攻击一致。
6. 更新 `battle_http_server.py` 的 `_ai_decide_action()`、`submit_action()`、`submit_reaction()`、目标解析、`get_alist()` 和 `_build_turn_announcement()`：在动作选择、API 校验和可用动作展示三个层面过滤非法行为，并显示当前状态及剩余回合；状态导致无攻击/施法动作时，击晕 AI 优先考虑可用的 `.a eat`/`.a give`，否则自动 `.i end`。反应入口必须拒绝击晕角色的手动或自动闪避、反击、格挡，并在攻击结算中按“无反应”继续。目标列表可继续显示击晕值为 0 的角色，但攻击类目标解析和 AI 选敌必须排除它，并注明“击晕保护：不可继续攻击”。

### 阶段三：替换先攻与动作经济
7. 在 `battle_engine.py` 将 `_get_dynamic_action_count()` 改为主动作计算器：`main_actions = max(1, effective_MOV // 5 + 回合行动次数)`，不设上限，使用飞行、减速、buff 和领域修正后的有效 MOV。删除/退役 `MAX_DYNAMIC_ACTIONS` 驱动的 `_sync_initiative_slots()`、`_ensure_dynamic_slots()`、`_suppressed` 和 `__actN` 扩槽行为；保留 `_resolve_uid()` 对旧存档/旧调用的兼容解析。
8. 修改 `FullBattleEngine.setup_battle()`、`FastBattleEngine.setup_battle()`、召唤/合并/动态加入角色、准备阶段转正式阶段和每轮重置：每个角色或召唤物仅生成一个先攻条目；首次进入战斗及每个新回合把 `主动` 重置为新公式结果，`附加` 保持现有规则（普通角色 3、模板/合并召唤物沿用现有配置）。回合仅在主动作耗尽或 `.i end` 后前进，单个先攻回合内可连续执行全部主动作。
9. 清理 `battle_http_server.py`、`ai_battle.py`、`ai_trainer.py` 中针对 `__actN`、行动槽抑制和硬编码 `主动:2` 的逻辑；训练、模拟、锦标赛必须通过引擎动作初始化/重置 helper 获取动作数。更新召唤物批处理，使一组召唤物的共享动作次数使用代表召唤物的有效 MOV 公式，且不会因旧多槽逻辑重复执行。

### 阶段四：AI 状态、SealDice 本地模式与显示同步
10. 在 `ai_trainer.py` 的 `encode_state()` 增加控制状态位或紧凑状态掩码，并提升状态维度/兼容填充版本；`get_available_actions()` 同步过滤沉默、缴械、击晕、禁锢，`execute_action()` 再做防御校验。现有 Q 表因状态维度和动作经济变化视为旧格式，加载时兼容填充但建议重新生成 `ai_weights.json` 与 `ai_weights_pvp.json`。
11. 在 `autocombat.js` 为 setab 0/1 增加与 Python 一致的状态 helper、状态写入/刷新/倒计时、动作过滤和移动/攻击校验；隔离通过标记并暂停本地被动效果实现。将所有 `{主动:2}` 初始化及每轮重置替换为 `max(1, effectiveMOV//5 + 回合行动次数)`，先攻表仍每角色一条；更新 `.alist`/回合提示/错误消息显示状态和动态主动作数。setab=2 的 JS 继续以 Python 响应为权威，仅负责渲染。
12. 更新 `autocombat/README.md` 和 `autocombat/TEST_PLAN.md`：记录状态效果数据格式、动作公式、飞行/减速结算顺序、隔离暂停语义，以及 setab 0/1/2 一致性测试。修改完成后运行 `reference/_merge_backend.py` 重新生成 `autocombat_backend.py`，确保单文件后端不覆盖源文件改动。

**Verification**
1. Python 单元级状态矩阵：分别施加七种状态，验证同类刷新取最大值、不同状态可并存、到期移除；减速和击晕从 `持续回合` 读取时长；隔离期间被动产物保持剩余回合且不生效，结束后恢复。
2. 动作限制矩阵：对 `.s0`、主动伤害/治疗/召唤、`.a sN`、`.a m`、`.a eat/give`、`.i end` 验证沉默/缴械/击晕/禁锢的允许与拒绝结果；重点验证击晕仍可吃/给物品但不能手动或自动反应。分别以击晕值 0 和 1 测试普通攻击、伤害法术、非伤害敌对效果和 AI 目标选择，确保 HTTP、AI 和引擎低层无法绕过。
3. MOV 与飞行：覆盖基础 MOV、buff/领域增减、多个减速倍率、飞行及飞行+减速组合，验证统一结算顺序；验证飞行本身不提供奖励骰，并以固定随机种子检查双方有效 MOV 相差不足 5、恰好 5 和大于 5 时均严格沿用既有高 MOV 方攻击优势规则。
4. 动作公式边界：MOV 为 0、4、5、9、10、18、带负面领域和飞行时，验证主动作分别按 `max(1, MOV//5+回合行动次数)` 初始化和每轮刷新；先攻表中每实体始终只有一条，召唤物和阶段转换同样成立。
5. 端到端 setab=2：人类与 AI 各自处于每种状态时执行完整回合，检查 `.alist`、回合公告、分页、反应暂停/恢复和多主动作连续执行。
6. AI 回归：运行小规模训练、`sim.py` 固定种子对局及 1v1 锦标赛烟测，确认无空动作死循环、旧 `__actN` 依赖或 Q 表维度异常；随后重新训练正式 PVP 权重。
7. setab 0/1 手工回归：创建本地战斗，逐项验证状态、MOV、动作刷新、效果倒计时和先攻显示与 setab=2 一致。
8. 运行 Python 语法/导入检查、JS 扩展诊断、现有测试计划核心流程；执行合并脚本后再次检查 `autocombat_backend.py` 语法和关键状态符号均已内联。

**Decisions**
- 击晕禁止移动、普通攻击、主动/附加技能以及所有手动/自动反应，但允许 `.a eat`、`.a give` 和 `.i end`；被动不关闭。
- 击晕的 `辅助效果值` 为攻击保护开关：`0` 表示不能继续成为普通攻击或伤害技能目标，`1` 表示仍可；持续时间读取 `持续回合`，非伤害敌对效果不受该保护限制。
- 隔离采用暂停后恢复：被动效果不生效且不倒计时，隔离结束后恢复原剩余时长。
- 飞行规则适用于所有飞行来源，统一为有效移动力 +8；飞行不直接给予攻击奖励骰。
- MOV 攻击优势以双方有效 MOV 比较，差值达到 5 时沿用项目既有的高 MOV 方优势规则。
- 主动作使用有效 MOV 且无上限；公式为 `max(1, MOV//5 + 回合行动次数)`。
- 沉默、缴械、击晕、禁锢、隔离、飞行的辅助效果值表示持续回合数；减速例外：辅助效果值表示小数 MOV 倍率，持续时间读取 `持续回合`。重复同类状态的持续时间取较大剩余值。
- 实施覆盖 setab 0/1/2、AI 训练、模拟和锦标赛；`autocombat_backend.py` 仅通过合并脚本更新。
- 反应动作保持现有规则，不被沉默/缴械/击晕额外禁止；若后续需要“击晕也不能反应”，作为独立规则变更处理。
