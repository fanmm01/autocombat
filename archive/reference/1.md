我把 `battle_engine.py` 里的实际实现跑了一遍验证（用 FastBattleEngine 实例化了领域实测），下面是当前真实行为。

## 一、结算时机

领域**不是**在"每个角色的回合开始"结算，而是在**每轮（round）所有角色行动完毕、`activeIndex` 回到 0 时**结算一次：

[battle_engine.py:2443](battle_engine.py#L2443) — `self._tick_down(); self._apply_zone_effects()`

顺序是：

1. `_tick_down()`（[battle_engine.py:4384](battle_engine.py#L4384)）：HP阈值触发 → 领域进入触发（`_process_zone_specials`）→ 所有效果 `remainingRounds - 1`，到 0 删除
2. `_apply_zone_effects()`（[battle_engine.py:6512](battle_engine.py#L6512)）：领域伤害 / 治疗 / 回MP 逐格结算 → 更新跟随中心 → `_apply_zone_attr_penalties` 重算属性削减

因为倒计时在结算之前，**持续 N 回合实际只结算 N-1 次**。实测（伤害固定为 4）：

| 持续回合 | 各轮实际伤害 |
|---|---|
| 1 | `[0, 0, 0, ...]` ← 完全不结算 |
| 2 | `[4, 0, 0, ...]` |
| 3 | `[4, 4, 0, ...]` |
| 5 | `[4, 4, 4, 4, 0, ...]` |

另外，施放当轮不结算（创建发生在角色回合内，轮首已经过了）。

## 二、叠加规则（两个独立通道，规则不同）

### 通道 A：每回合伤害 / 回复HP / 回复MP（数值型）

**领域条目从不会合并**——每次施放无条件 `effects.append(zone_entry)`（[battle_engine.py:3682](battle_engine.py#L3682)），持续回合、半径、施法者都各自独立。

叠加是在**结算时**用去重键实现的（[battle_engine.py:6545](battle_engine.py#L6545)）：

```python
pos_key = (ec, spell_name)          # (坐标, 技能名)
if not stackable and pos_key in processed_zone_positions: continue
processed_zone_positions.add(pos_key)
```

| 情形 | 同一格的实际结算 |
|---|---|
| **同名** + 非叠加 | 只算 **1 次**（先遍历到的那条） |
| **同名** + `可叠加:1` | N 条全算 |
| **不同名** + 非叠加 | N 条各算各的，全额叠加 |
| **不同名** + `可叠加:1` | N 条全算 |

实测固定伤害 4：`[甲]`→4，`[甲,甲]`→4，`[甲,乙]`→8，两个不同施法者的`[甲,甲]`→4，任意 `可叠加:1` 组合→8。

三个需要注意的点：

- **"同名"指技能名**（`spellName`），**不含施法者**。两个不同角色放同名领域、或同一角色重复施放，都会被吞掉。
- **去重键不含中心点**。两个同名领域即使中心不同，只要覆盖同一格就只算一个。
- **去重集合是伤害/治疗/回MP 共用的**（`processed_zone_positions` 只有一份）。所以"同名伤害领域 + 同名治疗领域"叠在一起时，**后者的治疗会被吞掉**——实测一个非叠加领域同时带 `伤害4 + 回复2`，站在里面的友方从 50 → 46（既没治疗也吃了伤害）。
- `可叠加: 2` 在 buff 路径只是 truthy，**没有"层数上限"语义**，写 2 和写 1 行为一样。

### 通道 B：`属性削减`

这条通道**完全不用名字**（[battle_engine.py:2805](battle_engine.py#L2805)）：

| 情形 | 结果 |
|---|---|
| 非叠加（任意条数、任意名字） | 同一属性组取**最强**一条 |
| `可叠加:1` | 全部求和 |

实测减闪避：同名两根 `-30` → `-30`；不同名 `-30 / -20` → `-30`；都标可叠加 `-30 / -20` → `-50`。

这是查询式的：只写入 `_zone_penalty_<属性组>` 缓存，真正取值在 `_zone_attr_mod`（[battle_engine.py:1375](battle_engine.py#L1375)），**从不改写基础属性**，所以领域消失后自动恢复。但缓存只在 `_apply_zone_effects` 里重算，因此**创建当轮不生效、回合中走进/走出领域也要等下一轮才生效**（实测：创建后立刻查是 0，轮首结算后是 -30，走到圈外仍是 -30，再结算一次才归 0）。

### 通道 C：其它效果（奖励骰、技能加减值）——**不存在**

`zone_entry` 只拷贝 `tickDmg / tickHealHp / tickHealMp / attributeDebuff / filter / centerFollows / on_enter_*`（[battle_engine.py:3682-3693](battle_engine.py#L3682-L3693)），**`辅助效果` / `辅助效果值` / `技能加减值` 根本没有被带进领域结构体**。所以写在 type=8 effect 里的奖励骰会静默失效。

## 三、你的具体问题：三回合领域 + 自己奖励骰

如果把 `辅助效果: 伤害成功率奖励惩罚 / 辅助效果值: b` 写在 type=8 的 effect 里——**永远不生效**。实测：领域结构体的 key 里没有 aux 字段，`_get_active_buffs` 里没有这条，`_calc_net_bp` 返回 `''`。

正确写法是**拆成同一个 spell 的两条 effect**（黑雾笼罩就是这么写的，[characters_data.py:906](characters_data.py#L906)，领域·灭同理）：

```python
{'name':'X领域', 'category':8, 'effects':[
    {'type':8, '客体':1, '作用半径':8, '持续回合':3, '属性削减':'闪避-30'},
    {'type':4, '客体':1, '持续回合':3, '辅助效果':'伤害成功率奖励惩罚', '辅助效果值':'b'},
]},
```

这样时间线是：

- **施放当轮**：buff 立刻可查，`_calc_net_bp` 已返回 `b`
- **之后每轮开始时**：`_tick_down` 把 `remainingRounds` 从 3→2→1→0 删掉。实测：施放轮 `b`，第 1 次轮首后 `b`（剩2），第 2 次后 `b`（剩1），第 3 次后消失
- 即有效期 = **施放回合 + 后续 2 轮**，与领域的 N-1 次伤害 tick 恰好对齐

关键语义是：**奖励骰不是"每回合发一次"，而是被动常驻状态**。`_get_active_buffs` 每轮只在 `remainingRounds != 0` 时返回它（[battle_engine.py:1811](battle_engine.py#L1811)），真正读取发生在**每次掷骰**时（`_calc_net_bp`，[battle_engine.py:461](battle_engine.py#L461)）。轮首的"结算"只是倒计时 + 刷新缓存，不会重新施加。

同名 buff 再次施放时**不叠层、只刷新时长**：同名 + 同 `auxType` + 同 `effectKey` 时 `remainingRounds = max(旧, 新)`（[battle_engine.py:3116-3125](battle_engine.py#L3116-L3125)），除非标 `可叠加`。想给更长的"领域在加值就在"，得用 `持续回合:99` + `linked_summon` 那种写法（如月中的倒影）。

## 四、顺带发现的几处不一致（你可能要修）

1. **`客体` 敌我过滤只对治疗生效，对伤害完全不生效**。tick 伤害循环（[battle_engine.py:6531](battle_engine.py#L6531)）只检查 `ally_safe`，不调 `_zone_includes`；治疗通道则硬编码 `entry.team != zone_team: continue`。实测 `客体=45` 的伤害领域照样烧队友、`客体=3` 的友方领域照样烧敌人。而 `ally_safe` 不在 `load_spells` 的字段白名单里（[battle_engine.py:2110](battle_engine.py#L2110)），**数据里写不进去**，等于无法规避。
2. **`on_enter_attr_debuff` 未实现**——只出现在 docstring 和结构体拷贝里，实测进入领域后 `斗殴` 修正为 0。目前只有 `on_enter_mp_drain_pct` 真正生效。
3. **`_apply_zone_effects` 有 3 份拷贝**（`CombatEngine` 空实现 [4726](battle_engine.py#L4726)、`FullBattleEngine` [6512](battle_engine.py#L6512)、`FastBattleEngine` [7152](battle_engine.py#L7152)），`autocombat_backend.py` 里还有 3 份。Fast 版缺 `self._zone_tick_results = tick_results`，而 `battle_http_server.py:1452` 读的正是这个属性（HTTP 服务用的是 FullBattleEngine，所以目前没暴露）。
4. **JS 版规则不同**：`autocombat.js` 的领域 tick（[autocombat.js:7185](autocombat.js#L7185)）没有同名去重、没有 `stackable`、tick 伤害不做敌我过滤；只有 `zoneAttrPenalty`（[autocombat.js:779](autocombat.js#L779)）实现了"非叠加取最强/叠加求和"。两套引擎的领域行为目前不一致。
