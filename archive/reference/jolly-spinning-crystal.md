# 计划书：完成 request.txt 全部内容 + 代码审查

## 背景

`request.txt` 描述了一个完整的 CoC 魔法少女战术战斗系统，包含两种自动化模式。`autocombat1.js`（v0.4.0, ~1590行）已实现了 `.setab 0` 的大部分功能和部分 `.setab 1` 基础设施，但完全自动化战斗引擎、法术系统、Excel 制表、升级机制等尚未实现。

## 新基线（autocombat1.js v0.4.0）已完成项

对比旧版 v0.3.0，新增了大量功能：

### 新增/改进的功能
- **rollD100 重写**：手动掷 d10 替代 `seal.format`，彻底解决奖励骰 NaN 问题
- **rankText 去 COC 模板依赖**：使用纯文本，不再依赖 `seal.formatTmpl`
- **战斗技能分类体系**：`ALL_COMBAT_SKILLS`(20项)、`MELEE_COMBAT_SKILLS`(9项)、`RANGED_COMBAT_SKILLS`(11项)、`RANGED_ALIASES`
- **isRangedSkill()** / **getBestMeleeSkill()**：远程判断 + 取最高近战技能
- **calcDamageValue()**：纯数值伤害计算（无文本输出），用于内部结算
- **calcDamageAndSyncCard()**：伤害计算 + 同步回角色卡
- **多次攻击 `n#`**：`.bta 3# 斗殴 @目标`，最多20次
- **远程攻击跳过反应**：直接结算伤害
- **`.bta start`**（btastart）：战斗前属性快照 + 战斗标记 + 初始化战斗HP
- **`.bta end`**（btaend）：战斗后同步HP回卡 + 清理状态
- **`.stb`**：战斗内直接修改HP（`+5`, `-3`, `10`）
- **`.hs` 增强所有战斗技能**：只要属性表有值就 +20（上限80）
- **`.hs` 自动 btastart**：变身同时开启战斗同步
- **`.unh` 优先使用战斗HP**：有战斗内HP则用战斗内HP计算恢复值
- **`.unh` 自动 btaend**：解除变身时清理战斗状态
- **反击默认最高近战技能**：不再硬编码"斗殴"
- **parseSkillValue "skill50" 改为替换**：不再累加
- **骰子表达式作为首参时视为伤害骰**：自动使用最高近战技能
- **`.e c 70` 纯数字识别为技能值**：而非伤害骰
- **大失败闪避/反击双向加成**：攻方大失败 → 防方+1；防方大失败 → 攻方+1/+2
- **onCommandReceived 钩子追踪 `.st` 修改**：战斗中 `.st` 修改 HP/MP/SAN 实时同步到 combat HP store

## 阶段三：.setab 1 战斗引擎核心（第甲节）

### 3a. 战斗状态数据结构
新增 storage 键：
- `combat_state_{groupId}` — 当前阶段、回合数、活跃角色索引、模式标记
- `combat_map_{groupId}` — 网格状态（尺寸、障碍物坐标集合、角色占据位置映射）
- `combat_initiative_{groupId}` — 先攻排序列表 [{userId, name, dex, roll, team, pos}]
- `combat_actions_{groupId}` — 每角色剩余行动数 {userId: {附加: 3, 主动: 2}}
- `combat_effects_{groupId}` — 活跃法术效果 [{spellId, sourceUserId, targetUserIds, remainingRounds, ...}]
- `combat_spells_{groupId}` — 每个角色加载的法术列表

### 3b. 地图系统
- **网格坐标**：字母列 + 数字行（A1, B3, F5...）
- **创建**：`.bta map 10*10` 生成 10×10 网格
- **入口**：始终在 A列 ceil(rows/2)（即中间行）
- **扩展**：`.bta map add 5*10 A11 blank` 在 A11 处扩展 5×10 空区域
- **障碍物**：`.bta map add 1*1 F5 none` 标记 F5 为障碍物
- **放置**：`.bta add Y12 A1` 将参与者放入 A1
- **渲染**：纯文本 Unicode 网格：
  ```
  ┌───┬───┬───┬───┬───┐
  │   │   │   │   │   │ 5
  ├───┼───┼───┼───┼───┤
  │ Y1│   │███│   │   │ 4
  ├───┼───┼───┼───┼───┤
  │   │   │   │ Z0│   │ 3
  ├──入口─┼───┼───┼───┤
  │   │   │   │   │   │ 2
  ├───┼───┼───┼───┼───┤
  │   │ Y2│   │   │   │ 1
  └───┴───┴───┴───┴───┘
    A   B   C   D   E
  ```
- **首选渲染方式**：借用 logai 中的图片渲染（主题系统），调用 `logai_server_release.py` 的 `text_to_images()` 函数将地图状态生成为 PNG 图片，通过 NapCat 上传到群内展示
- 纯文本 Unicode 网格作为降级方案（当 logai 后端不可用时）

### 3c. 先攻系统
- `.bta int team=Y pos=F/M/B card=本群卡`
  - 从角色卡读取 DEX，自动掷 1d100 纳入先攻排序
  - F(前部) = 入口前方第3格，M(中部) = 入口前方第2格，B(后部) = 入口前方第1格
  - 即从入口向外排列：入口 → B(1格) → M(2格) → F(3格)，越往前越接近敌方
  - 位置约束：目标格与入口距离 ≤ MOV
  - 同一格可堆叠多个角色（不做禁止，但不鼓励）
- `.bta start`
  - 锁定先攻表，打印参与者列表
  - 自动变身所有未变身 PC/NPC（调用 .hs 逻辑）
  - PC 编号：阵营名+魔法少女编号（如 Y1, Y2...）
  - 敌方编号：X0, Z0...（前缀+从0开始）
  - 快捷引用支持：Ys=同阵营全体, Yr=同阵营随机, S=自身

### 3d. 回合制战斗引擎
每回合：
1. **回合前**：展示地图 + 回合数 + 各角色剩余行动数
2. **回合中**：按先攻顺序每个角色执行完整行动序列：
   - 0. 回合开始，声明附加动作1（如果有）
   - 1a. 附加动作1（移动/技能/非战斗检定）
   - 1b. 主动作1（攻击/伤害技能）
   - 2a. 附加动作2
   - 2b. 主动作2
   - 2c. 附加动作3
   - 3. 结束回合
3. **回合后**：所有效果 tick（持续-1），结算回复/伤害，冷却递减
4. 检测战斗结束条件（全体敌方HP=0 或 全体友方HP=0）

### 3e. 行动指令

**指令体系**：不使用 `.c` 前缀。技能直接用 `.sN`，移动用 `.a m`，反应用 `.e`。

**主要行动**：
- `.a m A1` — 移动（消耗附加动作）
- `.a s1` — 附加动作释放技能1
- `.s0` — 主动作：基础近战攻击（等同于空 `.bta`，自动使用最高近战技能）
- `.s2 Y12` — 主动作：技能2 目标 Y12
- `.s2 @张三` — 主动作：技能2 目标为 @张三 所绑定的魔法少女序号
- `.s3 A1` — 主动作：技能3 中心点 A1
- `.s4 Y12 Y4` — 多目标技能4
- `.u xxx s1` — 使用物品的能力1

**@ 绑卡机制**：
- `@账号` 自动解析为该账号绑定的魔法少女序号
- 通过 `.as (序号)` 指令完成绑定：`.as Y1` → 当前发言者的 `.ra`/`.st` 等操作针对序号 Y1 的角色卡
- 之后其他玩家用 `@该人` 即可引用其魔法少女序号
- 适用于所有指令中的目标参数（`.s2 @某人`、`.bta @某人` 等）

**快捷战斗序列**（`.bta` 在 `.setab 1` 模式下的扩展用法）：
- `.bta s1 s2 X0` — 一键执行完整序列（附加动作 s1 + 主动作 s2 vs X0）
- `.bta a1s1Ys a2s1Zs a3mA5 s1 s2 X0` — 完整序列含多附加+多主动+多目标
- 客体标记：`X0Y1Zs` 等，前方有空格 = 全体的默认值；`Ys`=Y阵营全, `Yr`=Y阵营随机, `S`=自身

**反应动作**：
- `.e d` / `.e c` / `.e s1` — 闪避/反击/技能反应

### 3f. NPC 自动反应
- `.bta setreaction X1 d` — X1 默认闪避
- `.bta setreaction X1 c` — X1 默认反击
- 攻击有预设反应的 NPC 时跳过等待，直接结算
- NPC 使用存储的技能值进行反应检定

### 3g. 移动自动化
- 近战攻击：目标不在相邻格则自动移动（消耗附加动作 > 主动作）
- 远程攻击：检查攻击范围（默认无限，技能可限定），不在范围内则自动移动
- 移动沿最短路径（避开障碍物和已占据格）

### 3h. 战斗生命周期
- `.bta new <name>` → 创建模板
- `.bta import <name>` → 载入模板（初始化地图）
- 循环 `.bta int` → 加入参与者
- `.bta start` → 开始战斗
- 回合循环（系统自动管理，玩家用 `.a`/`.c`/`.bta` 行动）
- `.bta end` → 结束战斗，清理状态，触发战后处理
- 中间可用 `.bta save` 保存进度

## 阶段四：升级与熟练度（第乙.三节）

### 4a. 等级追踪与自动升级
- 追踪有效变身次数（`$gHsValidTransformCount` 或 storage key）
- 在 `.unh` 时若 spellCount>2 或 combatFlag>0，递增计数
- 升级节点：count ∈ {1, 3, 6, 10, 15, ...}（三角数 T_n = n(n+1)/2，取 n≥1）

### 4b. 魔法解锁
- count=4,8,12... → 提示解锁【深层魔法】（需kp确认）
- count=2,6,10... → 提示解锁【浅层魔法】（需kp确认）
- 任意升级 → 选一个已掌握魔法 +30 熟练度

### 4c. 熟练度系统
- 每法术独立存储：`熟练度_<法术名>`（在角色卡属性中）
- **获取熟练度**：
  - 升级时选一法术：+30
  - 法术大成功/成功终结：+30
  - 战斗中使用该法术：+1d20（战后结算）
- **熟练度阈值**（每个阈值从以下效果中**择一**，与kp商议后确定）：
  - 30 → 升级 Lv1：伤害骰提升一档（d4→d6→d8→d10→d12）**或** 吟唱时间减1/4 **或** 持续时间+1/3 **或** 致死骰+2 **或** 领域半径+1格，择一
  - 60 → 升级 Lv2：同上，再择一（可与前次不同）
  - 90 → 升级 Lv3：同上
  - 100 → 深化（升级为更深层模式，由kp设计）
- **升级效果实现方式**：通过重新执行 `.st` 录卡将升级后的数值写回角色卡（而非程序自动修改）。系统仅追踪熟练度数值和提示可选升级项，实际修改由 pl/kp 手动 `.st` 完成。
- `.setab 0` 模式下不自动结算升级（仅追踪）

### 4d. CM 集成
- `.cm` 快捷指令：掷 `1d100` 对比 `灵感 + CM`
  - 出目越大越好（与常规检定相反——这是知识检定）
  - kp 给出成功值
- 驾驶/信用：用 `.rd + 驾驶` / `.rd + 信用` 代替 `.ra驾驶` / `.ra信用`

### 5b. 法术加载与验证
- 战斗开始时（`.bta start`）从角色卡属性中扫描所有 `技能一`、`技能二`... 键
- 解析为结构化法术对象并缓存
- 验证必填字段（名称、类别、时机）
- 缺失字段使用默认值

### 5c. 法术执行引擎
按效果类别分发：

**伤害（类别含 1）**：
1. 若成功率>0 → 掷成功率检定
2. 若命中且 `可反应性=1` → 目标可选择反应动作（闪避/反击/技能反应）
3. 反应结算后若仍命中 → 计算伤害（复用 `calcDamageValue`，传入 `可贯穿性` 决定是否应用贯穿规则）
4. 检查致死骰
5. 应用附加效果（击飞/击晕）

**护盾（类别含 2）**：
1. 为目标添加临时护盾值
2. 护盾在受伤害时优先扣除
3. 持续回合结束后护盾消失

**回复（类别含 3）**：
1. 掷回复量骰子
2. 应用到目标 HP/MP/SAN
3. 不超过上限

**辅助（类别含 4）**：
1. 修改目标技能值/属性（加减值或百分比）
2. 效果持续若干回合
3. 效果类型映射表：受到伤害±/造成伤害±/mp回复±/hp回复±/魔能消耗±/致死骰优势劣势/伤害骰优势劣势/伤害成功率加减/奖励惩罚骰/以上成倍变化

**召唤（类别含 5）**：
1. 从召唤物模板创建实体
2. 加入先攻表
3. 持续回合结束后消失

**制造（类别含 6）**：
1. 为自身/目标创造物品
2. 物品属性通过法术参数定义

### 5d. 技能表模板（第陆节规格）
每个法术的 Excel 行需包含的字段见 2b 中的列定义。关键设计：
- 表头动态显示（IF 映射类别→列标题）
- 伤害骰公式自动计算期望值和致死阈值
- 导入区公式自动拼接 `.st` 命令
